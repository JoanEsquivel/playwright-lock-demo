# Usar el kit desde GitHub Copilot

Qué ficheros necesita una persona para empezar a usar las skills, el agente y las reglas de este repositorio desde GitHub Copilot (VS Code o CLI). Todo lo que Copilot lee vive en la raíz, en `.github/` y en `.claude/skills/`.

## 1. Imprescindibles (lo que Copilot lee directamente)

| Fichero / carpeta | Qué es | Cómo lo usa Copilot |
|---|---|---|
| `AGENTS.md` | Contrato de estándares: parámetros, layout, reglas no negociables, estilos de test | Se carga automáticamente en cada sesión |
| `.github/copilot-instructions.md` | Instrucciones siempre activas; apunta a `AGENTS.md`, a las rules y a las skills | Siempre activo |
| `.github/agents/qa-playwright-engineer.agent.md` | Agente custom `qa-playwright-engineer` | Aparece en el selector de agentes de VS Code y en `copilot --agent qa-playwright-engineer` |
| `.github/instructions/*.instructions.md` (`api`, `ci`, `fixtures`, `pages`, `tests`) | Rules por ruta con `applyTo` | Se activan al tocar `pages/**`, `tests/**`, `api/**`, `fixtures/**`, `.github/**` |
| `.claude/skills/` (las 7 carpetas completas) | `playwright-architecture`, `playwright-scaffold`, `playwright-create-test`, `playwright-fix-test`, `playwright-delete-test`, `playwright-ci`, `playwright-cli` | Copilot descubre skills en `.claude/skills/` sin configuración extra |

Cada skill hay que copiarla **entera**: `SKILL.md` más sus `references/`, `templates/` y `scripts/`. Solo el `SKILL.md` no basta (por ejemplo, `playwright-scaffold` depende de `scripts/scaffold.mjs` y de `templates/`).

## 2. Fuentes de verdad (solo si van a mantener el kit, no solo consumirlo)

| Fichero / carpeta | Para qué |
|---|---|
| `.claude/rules/*.md` | Origen de `.github/instructions/*.instructions.md` |
| `.claude/agents/qa-playwright-engineer.md` | Origen de `.github/agents/qa-playwright-engineer.agent.md` |
| `scripts/sync-agent-config.mjs` + scripts `sync:agents` / `sync:agents:check` en `package.json` | Regeneran `.github/instructions`, `.github/agents` y `.github/copilot-instructions.md` |

Si solo van a usar Copilot y nunca editar las rules ni el agente, pueden copiar los ficheros generados de `.github/` y omitir este bloque. Los generados llevan una cabecera `GENERATED by scripts/sync-agent-config.mjs`; no se editan a mano.

## 3. Entorno para que el agente funcione de verdad

```bash
cp .env.example .env          # BASE_URL, E2E_USERNAME, E2E_PASSWORD (+ API_* si hay capa API)
pnpm install
pnpm exec playwright install chromium --with-deps
pnpm test:setup               # login una vez → .auth/user.json
```

- `.env` con los parámetros del target. Las skills nunca asumen URLs ni credenciales.
- `playwright-cli` instalado (ya es dependencia en `package.json`): las skills lo usan para verificar locators en la página real antes de escribirlos.
- Dependencias del proyecto instaladas para que `lint` y `playwright test` (la definición de hecho) puedan ejecutarse.

## 5. Cómo invocar

| Herramienta | Gesto |
|---|---|
| Copilot en VS Code | Elegir `qa-playwright-engineer` en el selector de agentes del chat, o escribir `/qa-playwright-engineer <prompt>` |
| Copilot CLI | `copilot --agent qa-playwright-engineer --prompt "<prompt>"` |

Prompts recomendados y qué esperar de cada uno: `docs/agent-guide.md`, sección 4.

## 6. Checklist mínimo para copiar a otro repo

```
AGENTS.md
.env.example
.github/copilot-instructions.md
.github/agents/qa-playwright-engineer.agent.md
.github/instructions/*.instructions.md
.claude/skills/**            (las 7 carpetas completas)
```

Opcional, para mantener el kit:

```
.claude/rules/*.md
.claude/agents/qa-playwright-engineer.md
scripts/sync-agent-config.mjs   (+ scripts sync:agents en package.json)
```

## 7. Nota sobre la ruta de las skills

`copilot-instructions.md` y el agente referencian las skills por la ruta `.claude/skills/`. Copilot también soporta `.github/skills/`; si alguien las mueve ahí, debe actualizar la ruta en `scripts/sync-agent-config.mjs` y ejecutar `pnpm sync:agents`.
